# Security Policy

## Scope

This policy covers the public website source in this repository and security issues that may affect official eeFunction web properties.

The proprietary eeFunction application and calculation engine are maintained separately. Reports involving the application, licensing, update delivery, or commercial services should still follow the private-reporting guidance below.

## Do not report publicly

Do not open a public issue for:

- exposed credentials, tokens, secrets, or signing information;
- authentication or authorization bypasses;
- license-verification bypasses;
- cross-site scripting, request forgery, injection, or data exposure;
- malicious or compromised downloadable files;
- customer data, private workbooks, or personally identifiable information;
- vulnerabilities that could be actively exploited before a fix is available.

## Private reporting

Until a dedicated security email address or GitHub private vulnerability reporting channel is published, use GitHub's private security advisory feature for this repository when available. Include:

- affected URL, version, commit, or component;
- clear reproduction steps;
- expected and actual behavior;
- impact assessment;
- supporting screenshots or proof-of-concept material with sensitive values removed;
- any suggested mitigation.

Do not include live credentials or unnecessary personal data.

## Response process

BRBRSoft will aim to:

1. acknowledge a valid report;
2. assess scope and severity;
3. prepare and test a correction;
4. coordinate disclosure where appropriate;
5. publish release or security notes after affected users can mitigate the issue.

No fixed response-time commitment is made until a formal commercial support policy is published.

## Supported versions

The website currently has no production release. Supported versions and deployment channels will be listed here once the first public version is released.
